## Verification

`forge script script/DeployV4.s.sol --sig "verify()" --rpc-url <chain>` checks the deployed stack against
`EXPECTED_*`. It also checks V4's wiring to the gas policy and the table, the helper's `checkStack()` (the pinned
Safe stack and CCTP on that chain), the table's contents, that none of the six contracts carries a guardian, pause or
admin selector, and that the ModuleRegistry records the relayer as the sender of V4 and the gas policy. It was run after the broadcast, then again from the
pin branch at the same commit. Exit codes: Base 0, Ethereum 0, Monad 0. Every run returned
`Stack({ table: 0x1e3a…3Ad3, gasPolicy: 0xEF86…6C5C, policy: 0xCd27…f2d8, check: 0xc040…fB31 })`.

Sourcify, read on 3 Nov after the deploy: `MamoruRemoteInit` is `exact_match` on Base and Ethereum. None of the other
four contracts is verified on any chain yet, and `MamoruRemoteInit` is not verified on Monad. Submitting the sources is
still open.

## Registry

`packages/registry/{base,ethereum,monad}.json` pin the five contracts as entries, and `undeployed` is empty. Each role
says that its code hash was read at the block above and not at the file's pin block, as T7 and `MamoruMigrationCheck`
did. `pin.ts` in verify mode reads at the pin block, so it reports no code for these entries until the files are
re-pinned at a later block.
